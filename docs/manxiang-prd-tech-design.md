# 慢想 PRD 与技术设计 v0.1

## 1. 产品定位

### 1.1 一句话定位

慢想是一个从「随手收藏」开始的研究伙伴，帮助用户把零散链接、实时感想和临时好奇，慢慢整理成有主线、有证据、有边界的知识地图，并在需要时升级成主题报告。

### 1.2 要解决的问题

用户经常因为一个视频、一条推文、一篇文章对某个领域产生兴趣，但后续会遇到几个问题：

- 收藏很多资料，但不知道它们之间有什么关系。
- 搜索越多越乱，看似学了很多，实际没有形成记忆和结构。
- 容易被某个细节吸引，钻进分支，忘记最初想研究的问题。
- 有一个概念没理解就卡住，导致整体阅读效率很低。
- 想写主题报告，但缺少主线、证据组织和自然表达能力。
- 不希望 Agent 从零代写，而是希望 Agent 帮自己整理、追问、收束和润色。

慢想的核心不是「帮用户看更多」，而是「帮用户少跑偏、慢慢想清楚」。

### 1.3 产品原则

1. 先收下，不急着研究。
2. 先看整体，再钻细节。
3. 先形成主线，再补证据。
4. 被拒绝展开的兴趣不能丢，要放进停车场。
5. Agent 可以强势干预，但必须解释原因。
6. 用户有最终选择权，但 Agent 必须提示选择带来的风险。
7. 知识地图是默认产出，主题报告是升级产物。

### 1.4 产品不是做什么

慢想第一版不做下面这些事：

- 不做通用知识库。
- 不做无限搜索助手。
- 不做自动洗稿工具。
- 不做单纯的网页总结器。
- 不做复杂知识图谱平台。
- 不提供医学诊断或治疗建议。

它可以辅助注意力管理和研究收束，但不能替代专业医学帮助。

### 1.5 长期架构方向：外部知识库 + 流程 Agent

慢想的长期方向不是自己变成一个大而全知识库，而是接入本地或云端知识库，让知识库承担长期保存、检索、引用和同步，慢想 Agent 只承担研究流程中的判断与编排。

核心边界：

- 数据库/知识库负责保存原始来源、抽取片段、向量索引、历史版本、证据引用和归档结果。
- 慢想 Agent 负责发现主题、判断成熟度、推荐主线、管理研究边界、生成知识地图、提示证据缺口和引导写作升级。
- 慢想不把“存了很多资料”当成成功，而是把“用户是否更清楚自己在研究什么”当成成功。
- 慢想可以读写知识库，但不能把知识库里所有内容都自动扩展成研究任务。
- 知识库是长期记忆，Agent 是研究过程管理器。

这意味着未来实现时要优先抽象 `KnowledgeRepository` / `SourceRepository` 这类接口，而不是把业务逻辑绑死在某一种数据库上。第一版可以继续用本地 JSON 验证流程，后续再替换成 SQLite、向量库、Notion、云数据库或混合存储。

## 2. 用户场景

### 2.1 场景一：随手收藏一个刺激点

用户刷到一个视频，觉得里面关于「AI 陪伴」的观点很有意思，于是把链接丢进慢想，并补一句感想：

> 明知道是 AI，但为什么有人还是会觉得被理解？

慢想只做轻量处理：

- 保存链接。
- 记录用户原始感想。
- 自动生成初步标签。
- 不主动展开研究。
- 不连续追问。

目标是降低收藏成本，避免用户刚收藏就被拖进深坑。

### 2.2 场景二：收藏达到触发条件

当某个主题簇积累到一定数量，慢想触发主题发现。

示例触发条件：

- 全局收藏满 15 条，触发轻量回看。
- 某个主题簇满 5 条，触发主题发现。
- 某个问题反复出现 3 次，提示是否升级为研究任务。
- 某条实时感想被标记为强触动，进入候选主题。

慢想输出三种可选结果：

- 主题清单：告诉用户最近在关注什么。
- 研究建议：推荐最值得深入的 1-2 个主题。
- 半成品报告骨架：仅对成熟主题开放。

默认先输出主题清单，不直接生成重型内容。

### 2.3 场景三：从主题升级为研究任务

用户从主题雷达中选择一个主题，例如「AI 陪伴与亲密关系」。

慢想会先生成研究契约：

- 当前主题是什么。
- 本轮目标是什么。
- 默认产出是什么。
- 推荐主线是什么。
- 哪些内容允许深入。
- 哪些内容进入停车场。
- 当前 Agent 模式是什么。

示例：

```text
主题：AI 陪伴与亲密关系
默认产出：知识地图
推荐主线：因果线
本轮目标：解释 AI 陪伴为什么会让人产生真实陪伴感
允许深入：用户心理、产品机制、典型案例
暂不展开：底层模型架构、语音克隆技术史、融资细节
模式：温和编辑型
```

### 2.4 场景四：生成文本 + 树状图双视图

慢想默认生成知识地图，不默认生成长报告。

知识地图包含两种视图：

- 文本视图：解释主线、推荐理由、证据状态和下一步。
- 树状图视图：展示主题、核心问题、主线节点、关键概念、证据材料、证据缺口和停车场。

树状图第一版只做只读导航，不做复杂拖拽。

### 2.5 场景五：用户跑偏时 Agent 干预

如果用户想深入一个偏离主题的细节，慢想根据模式进行干预。

示例：

```text
这个分支有价值，但它会把本轮研究从「AI 陪伴为什么让人产生真实感」
带到「语音克隆技术史」。

我会先把它放进停车场。
当前建议继续处理主线节点：记忆与人格化如何增强陪伴感。
```

干预不是否定兴趣，而是保护当前任务。

### 2.6 场景六：补证据阶段联网搜索

慢想支持联网搜索，但只在补证据阶段开放。

搜索前必须明确：

- 证据缺口是什么。
- 搜索目标是什么。
- 停止条件是什么。

示例：

```text
证据缺口：缺少用户为什么长期使用 AI 陪伴产品的材料。
搜索目标：寻找 2-3 条用户研究、产品数据或行业分析。
停止条件：找到能支撑该节点的证据后停止，不扩展新主题。
```

搜索结果只能服务当前主线，不能直接扩展成新研究任务。

## 3. 核心流程

### 3.1 总流程

```text
随手收藏
  ↓
补一句实时感想
  ↓
轻量归档
  ↓
主题发现触发
  ↓
生成主题清单
  ↓
用户选择候选主题
  ↓
推荐主线
  ↓
生成知识地图
  ↓
标出证据缺口
  ↓
必要时进入补证据
  ↓
更新知识地图
  ↓
可选升级为报告或短札记
  ↓
复盘归档
```

### 3.2 收藏阶段

收藏阶段的目标是低成本记录，不展开研究。

输入：

- 链接。
- 文本。
- 截图说明。
- 视频笔记。
- 用户实时感想。

Agent 行为：

- 生成简短摘要。
- 提取初步标签。
- 判断可能主题。
- 记录用户原话。
- 不主动联网。
- 不生成长篇分析。

### 3.3 主题发现阶段

主题发现阶段的目标是从收藏中发现重复出现的兴趣。

Agent 输出：

- 最近形成的主题簇。
- 每个主题簇的成熟度。
- 用户反复出现的感想关键词。
- 建议动作。

主题成熟度：

```text
碎片期：零散兴趣，不适合开题。
聚集期：开始重复出现，可以做知识地图。
成型期：资料和问题基本足够，可以升级为研究任务。
沉淀期：已经产出过，可以补充或更新。
```

### 3.4 研究立项阶段

研究立项阶段的目标是把一个主题变成一个有完成定义的任务。

必须确定：

- 研究主题。
- 本轮目标。
- 默认产出。
- 主线组织方式。
- Agent 模式。
- 完成定义。

默认产出：

```text
知识地图
```

可选升级产出：

- 主题报告。
- 短札记。
- 问题清单。
- 资料卡合集。

### 3.5 主线推荐阶段

慢想支持五种主线组织方式：

- 因果线：回答「为什么会这样」。
- 时间线：回答「它是怎么发展到今天的」。
- 问题线：回答「我要逐步搞懂哪些问题」。
- 人物/利益线：回答「谁推动、谁受益、谁被影响」。
- 情绪/个人触动线：回答「我为什么被它吸引」。

Agent 必须推荐一条主线，并可给出 1-2 条辅助视角。

推荐依据：

- 收藏内容结构。
- 用户实时感想。
- 反复出现的问题。
- 资料是否有时间顺序。
- 是否涉及人物、平台、公司、监管或利益关系。
- 默认产出目标。

用户可以否决 Agent 推荐，但 Agent 必须先提醒风险。

示例：

```text
我推荐因果线，因为你的资料主要在解释「为什么 AI 陪伴让人产生依赖」。

如果切换到情绪线，可以让表达更自然，但逻辑严谨度会下降。
建议折中：用情绪线开头，用因果线展开正文。
```

### 3.6 知识地图阶段

知识地图是慢想的默认产出。

地图固定包含：

- 核心问题。
- 推荐主线。
- 关键概念。
- 证据材料。
- 证据缺口。
- 分支停车场。
- 下一步动作。

第一版限制：

- 核心问题最多 1 个。
- 主线最多 1 条。
- 辅助视角最多 2 条。
- 主线节点 3-5 个。
- 关键概念最多 7 个。
- 证据材料最多 10 条。
- 下一步动作只给 1 个。
- 停车场不限数量，但默认不展开。

### 3.7 补证据阶段

只有当知识地图标出明确证据缺口时，才进入补证据阶段。

允许行为：

- 联网搜索。
- 补充来源。
- 核查事实。
- 判断证据强弱。
- 将证据绑定到主线节点。

禁止行为：

- 无目标搜索。
- 因新资料开启新主题。
- 将弱相关资料硬塞进正文。
- 为了显得全面无限扩展背景。

### 3.8 写作升级阶段

知识地图确认后，用户可以选择升级为：

- 主题报告。
- 短札记。
- 报告骨架。

写作 Agent 必须遵守知识地图中的主线、证据和停车场约束。

如果证据不足，Agent 不能直接写成确定结论，必须标注：

- 已有证据支持。
- 推测。
- 待核查。
- 个人感想。

## 4. Agent 架构

### 4.1 对用户呈现的形态

对用户来说，慢想只有一个 Agent：研究伙伴。

它可以切换三种模式：

- 严格导师型。
- 温和编辑型。
- 研究搭子型。

内部可以拆成多个角色，但用户不需要感知多 Agent 协作细节。

### 4.2 内部角色

慢想内部角色只做“研究流程判断”，不直接承担长期知识库职责。它们可以向知识库读取上下文，也可以把确认后的来源、证据、地图和复盘结果写回知识库，但不把自身设计成存储系统。

#### 4.2.1 收藏处理器

职责：

- 接收链接、文字、截图说明和实时感想。
- 生成轻量摘要。
- 提取标签和候选主题。
- 保存用户原始表达。

不能做：

- 不主动联网搜索。
- 不展开深度分析。
- 不直接生成报告。

#### 4.2.2 主题发现器

职责：

- 聚类收藏内容。
- 发现重复出现的问题、情绪和兴趣方向。
- 计算主题成熟度。
- 推荐候选研究任务。

不能做：

- 不能代替用户决定必须研究什么。
- 不能把碎片期主题直接升级为长报告。

#### 4.2.3 任务导航器

职责：

- 维护当前研究契约。
- 控制任务阶段。
- 推荐主线。
- 判断跑偏。
- 管理停车场。
- 控制模式切换。

这是权力最大的角色。

不能做：

- 不能删除用户兴趣。
- 不能无解释地拒绝用户。
- 不能跳过用户确认直接切换主线。

#### 4.2.4 证据整理器

职责：

- 只在补证据阶段工作。
- 根据证据缺口搜索资料。
- 提取事实、观点、案例和来源。
- 判断证据能支撑哪个主线节点。
- 标注证据强弱。

不能做：

- 不能无目标搜索。
- 不能因为搜索结果有趣就扩展新主题。
- 不能编造来源。

#### 4.2.5 写作编辑器

职责：

- 将知识地图升级成报告骨架、短札记或主题报告。
- 去掉 AI 味。
- 保留用户个人表达。
- 根据用户修改沉淀风格偏好。

不能做：

- 不能绕过证据限制。
- 不能把停车场内容擅自写进主线。
- 不能把推测写成事实。

### 4.3 三种模式

#### 严格导师型

适合：

- 用户已经确定目标。
- 需要高效率完成知识地图或报告。
- 跑偏风险高。

策略：

- 跑偏容忍度低。
- 深入层数 1-2 层。
- 打断频率高。
- 分支默认进入停车场。
- 可以拒绝继续展开偏题内容。

#### 温和编辑型

适合：

- 用户有资料，但结构还乱。
- 需要整理、收束和形成脉络。

策略：

- 跑偏容忍度中。
- 深入层数 2-3 层。
- 定期收束。
- 可以限制分支探索时间。

#### 研究搭子型

适合：

- 用户刚开始探索。
- 还不知道自己真正关心什么。

策略：

- 跑偏容忍度高。
- 允许发散。
- 打断频率低。
- 阶段性总结，不轻易拒绝。

### 4.4 强势干预协议

当用户跑偏时，Agent 分三级干预：

```text
一级：提醒
这个问题有趣，但它现在只和主线弱相关。我先放进停车场。

二级：限制
可以查，但只允许深入 5 分钟，目标是搞清楚它和主线有没有关系。

三级：拒绝
这个分支已经偏离本轮目标。我不会继续展开。
如果你坚持，我们需要把它升级成新的研究主题。
```

如果用户连续 2-3 次回到同一个分支，Agent 应判断这可能不是跑偏，而是新主题浮现。

此时给出选择：

```text
1. 继续原主题，把该分支作为小节。
2. 切换主题，把该分支作为新研究任务。
3. 暂停当前任务，先做该分支的知识地图。
```

### 4.5 数据层边界

慢想 Agent 访问数据层时应通过接口，而不是直接依赖具体存储实现。

建议分成三类仓储：

- `SourceRepository`：保存链接、文件、图片、视频等原始来源的元数据、抽取文本、引用锚点和内容哈希。
- `KnowledgeRepository`：保存主题、研究任务、知识地图、证据节点、停车场、报告草稿和复盘归档。
- `EventRepository`：保存事件日志、变更 diff、checkpoint 和 replay 所需信息。

本地 JSON 只是 MVP 的 `Repository` 实现，用来验证流程。未来可以替换或组合：

- 本地 SQLite + 文件目录。
- 本地向量库。
- Notion / Obsidian / Logseq。
- 云端数据库 + 对象存储。
- 私有知识库 API。

替换存储时，Agent 流程不应该大改。需要变化的是仓储适配器，而不是 `CaptureProcessor`、`TopicDiscoverer`、`TaskNavigator` 和 `KnowledgeMapBuilder` 的核心判断。

## 5. 状态机设计

### 5.1 收藏项状态

```text
NEW
  ↓
CAPTURED
  ↓
LIGHT_TAGGED
  ↓
CLUSTERED
  ↓
USED_IN_TASK / PARKED / ARCHIVED
```

状态说明：

- NEW：刚输入，还未处理。
- CAPTURED：已保存原始内容和感想。
- LIGHT_TAGGED：已生成摘要和标签。
- CLUSTERED：已归入主题簇。
- USED_IN_TASK：已进入某个研究任务。
- PARKED：暂不处理。
- ARCHIVED：已归档。

### 5.2 主题簇状态

```text
FRAGMENT
  ↓
GATHERING
  ↓
READY
  ↓
TASK_CREATED
  ↓
SETTLED
```

状态说明：

- FRAGMENT：碎片期。
- GATHERING：聚集期。
- READY：成型期，可以建议升级。
- TASK_CREATED：已创建研究任务。
- SETTLED：已经产出并沉淀。

### 5.3 研究任务状态

```text
CANDIDATE
  ↓
SCOPING
  ↓
LINE_CHOSEN
  ↓
MAP_DRAFTED
  ↓
EVIDENCE_GAP_FOUND
  ↓
EVIDENCE_PATCHING
  ↓
MAP_CONFIRMED
  ↓
OPTIONAL_WRITING
  ↓
REVIEWED
  ↓
ARCHIVED
```

状态说明：

- CANDIDATE：候选研究任务。
- SCOPING：正在确定目标、产出和边界。
- LINE_CHOSEN：已选择主线。
- MAP_DRAFTED：已生成知识地图草稿。
- EVIDENCE_GAP_FOUND：发现证据缺口。
- EVIDENCE_PATCHING：正在补证据，可联网。
- MAP_CONFIRMED：知识地图确认。
- OPTIONAL_WRITING：可选写作升级。
- REVIEWED：用户复盘完成。
- ARCHIVED：归档。

### 5.4 阶段权限

| 阶段 | 可联网 | 可写报告 | 可强势干预 | 默认产出 |
| --- | --- | --- | --- | --- |
| 收藏 | 否 | 否 | 低 | 收藏项 |
| 主题发现 | 否 | 否 | 中 | 主题清单 |
| 立项 | 否 | 否 | 中 | 研究契约 |
| 知识地图 | 否 | 否 | 高 | 文本 + 树状图 |
| 补证据 | 是 | 否 | 高 | 证据补丁 |
| 写作升级 | 仅事实核查 | 是 | 中 | 报告/短札记 |
| 复盘归档 | 否 | 否 | 低 | 沉淀记录 |

### 5.5 主线切换状态

```text
RECOMMENDED
  ↓
USER_OVERRIDES
  ↓
RISK_EXPLAINED
  ↓
USER_CONFIRMED
  ↓
LINE_SWITCHED
```

规则：

- Agent 必须先推荐主线。
- 用户可以选择其他主线。
- 用户选择低匹配主线时，Agent 必须提示风险。
- 用户确认后允许切换。
- 原推荐主线保留为备用方案。

## 7. MVP 范围

### 7.1 MVP 目标

验证一个核心闭环：

> 用户随手收藏内容后，慢想能否发现主题，并把其中一个主题整理成文本 + 树状图知识地图。

### 7.2 MVP 必做功能

1. 收藏箱

- 支持输入链接和文字。
- 支持补一句实时感想。
- 保存原始内容。
- 自动生成摘要、标签和候选主题。

2. 主题雷达

- 按主题聚类收藏。
- 显示主题成熟度。
- 输出主题清单和研究建议。

3. 研究任务工作台

- 从主题创建研究任务。
- 选择 Agent 模式。
- 生成研究契约。
- 推荐主线。
- 允许用户切换主线，并提示风险。

4. 知识地图

- 生成文本视图。
- 生成只读树状图。
- 显示核心问题、主线节点、关键概念、证据材料、证据缺口和停车场。

5. 跑偏干预

- 支持停车场。
- 支持三级干预文案。
- 支持分支升级为新主题的提示。

6. 补证据

- 只在补证据阶段允许联网。
- 搜索必须绑定证据缺口。
- 搜索结果必须绑定主线节点。

### 7.3 MVP 不做功能

- 不做复杂拖拽图谱。
- 不做多人协作。
- 不做浏览器插件。
- 不做自动视频转录。
- 不做移动端完整体验。
- 不做长期全局知识图谱。
- 不做全自动成稿发布。
- 不做医学相关诊断。

### 7.4 MVP 成功标准

定性标准：

- 用户能从收藏中看到自己反复关心的主题。
- 用户觉得知识地图帮自己看清了整体。
- 用户被跑偏干预时不觉得被冒犯。
- 用户愿意把某个主题继续推进到补证据或写作。

定量指标：

- 收藏到主题发现的转化率。
- 主题发现到研究任务的转化率。
- 研究任务到知识地图完成率。
- 停车场分支被接受率。
- 用户手动修改主线推荐的比例。
- 用户对知识地图的满意度评分。

## 8. 后续迭代

### 8.1 v0.2：报告升级

在知识地图确认后，支持一键升级为：

- 报告骨架。
- 短札记。
- 主题报告初稿。

重点不是快速生成长文，而是让写作严格遵守知识地图和证据边界。

### 8.2 v0.3：风格记忆

记录用户对文本的修改偏好：

- 不喜欢的 AI 味表达。
- 常用词。
- 喜欢的段落节奏。
- 更像用户自己的表达方式。

目标是让写作编辑器越来越像用户的表达助手，而不是套模板。

### 8.3 v0.4：浏览器收藏插件

支持用户在浏览器中一键收藏：

- 当前网页链接。
- 选中文本。
- 截图。
- 一句实时感想。

插件仍然遵守收藏阶段规则：只收，不展开。

### 8.4 v0.5：可编辑图谱

支持用户在树状图中：

- 调整节点顺序。
- 将停车场节点升级为主线节点。
- 将主线节点降级为辅助节点。
- 查看每次调整的风险提示。

第一版只读图谱跑通后再做。

### 8.5 v0.6：长期主题档案

将完成的研究任务沉淀为长期档案：

- 已完成的知识地图。
- 已写报告。
- 证据卡。
- 停车场分支。
- 可复用的主线模板。

注意：长期档案是研究任务的副产品，不要把产品重心变成传统知识库。

### 8.6 v0.7：知识库适配层

在流程稳定后新增知识库适配层，让慢想可以连接本地或云端知识库。

目标：

- 从知识库读取历史收藏、来源片段、已有主题和旧知识地图。
- 把新产生的主题、任务、证据、地图、checkpoint 和草稿写回知识库。
- 支持本地优先，也支持云端同步。
- 保留来源引用和变更历史，方便回溯。
- 不让知识库反过来驱动 Agent 自动无限研究。

这一阶段的重点不是做一个新的知识库产品，而是让慢想成为知识库上的研究流程层。

## 9. 关键风险与应对

### 9.1 风险：收藏箱变成垃圾堆

应对：

- 必须要求用户补一句实时感想。
- 主题发现按主题簇成熟度触发，不只按数量触发。
- 碎片期主题不能直接升级成长报告。

### 9.2 风险：知识地图也变得过度复杂

应对：

- 限制节点数量。
- 默认只展示主线和少量关键节点。
- 停车场默认不展开。
- 下一步动作只给一个。

### 9.3 风险：Agent 太强势，让用户反感

应对：

- 每次拒绝必须解释原因。
- 被拒绝的兴趣必须保存。
- 用户保留最终选择权。
- 严格程度可切换。

### 9.4 风险：联网搜索导致信息膨胀

应对：

- 只在补证据阶段开放。
- 搜索前必须有证据缺口、搜索目标和停止条件。
- 搜索结果只能绑定已有主线节点。

### 9.5 风险：写作结果有 AI 味

应对：

- 写作前先确认主线和证据。
- 避免万能套话。
- 保留用户原始感想。
- 区分事实、观点、推测和个人表达。
- 根据用户修改沉淀风格偏好。

## 12. 总结

慢想的核心价值不是替用户生产内容，而是帮助用户把注意力从无限资料中收回来。

它从收藏开始，但不止于收藏；它能发现主题，但不替用户决定兴趣；它能强势干预，但不丢掉用户的好奇；它默认产出知识地图，而不是急着生成长文。

第一版最重要的验证问题是：

> 慢想能不能把用户随手收藏的内容，整理成一张有主线、有证据边界、有停车场的知识地图？

如果这个闭环成立，再扩展报告写作、风格记忆、浏览器插件和长期档案。
